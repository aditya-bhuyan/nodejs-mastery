Chapter 3 — Asynchronous JavaScript & the Event Loop Intermediate

3.1 Why Asynchronous?

Node.js is single-threaded — there is only one main thread of execution. If a long-running operation (reading a large file, querying a database, making an HTTP request) were to block this thread, no other request could be handled until it finished.

Asynchronous I/O solves this: instead of waiting, Node.js registers a callback, hands the work off to the OS or a thread-pool worker, and immediately continues processing other events. When the work completes, the callback is placed on the event queue and executed when the call stack is empty.

3.2 The Event Loop

The event loop runs continuously and processes tasks in phases:

  1. timers — executes callbacks scheduled by setTimeout / setInterval
  2. pending callbacks — I/O callbacks deferred from the previous iteration
  3. idle / prepare — internal use
  4. poll — retrieves new I/O events; blocks here when there is nothing to do
  5. check — setImmediate callbacks
  6. close callbacks — e.g. socket.on("close", ...)

Between each phase, Node.js drains the microtask queue (resolved Promises and process.nextTick callbacks).

3.3 Callbacks

The original async pattern in Node.js. The convention is error-first: the first argument of the callback is always an error (or null).

const fs = require("fs");

fs.readFile("./data.txt", "utf8", (err, content) => {
  if (err) {
    console.error("Error reading file:", err.message);
    return;
  }
  console.log(content);
});

console.log("This prints BEFORE the file is read!");

Nested callbacks lead to "callback hell" — deeply indented, hard-to-read code. Promises were introduced to solve this.

3.4 Promises

A Promise represents a value that will be available in the future. It is either pending, fulfilled, or rejected. 

const fs = require("fs").promises; // or require("fs/promises")

fs.readFile("./data.txt", "utf8")
  .then(content => {
    console.log(content);
    return fs.writeFile("./copy.txt", content); // chain another promise
  })
  .then(() => console.log("File copied!"))
  .catch(err => console.error("Error:", err.message))
  .finally(() => console.log("Done."));

3.5 async / await

async/await is syntactic sugar over Promises — it makes async code look and read like synchronous code. An async function always returns a Promise. await pauses execution of the async function only (not the entire thread) until the Promise resolves. 

const fs = require("fs/promises");

async function copyFile(src, dest) {
  try {
    const content = await fs.readFile(src, "utf8");
    await fs.writeFile(dest, content);
    console.log(`Copied ${src} → ${dest}`);
  } catch (err) {
    console.error("Copy failed:", err.message);
  }
}

copyFile("./data.txt", "./copy.txt");

3.6 Promise.all, Promise.race, Promise.allSettled

const p1 = fetch("https://api.example.com/users");
const p2 = fetch("https://api.example.com/posts");

// Wait for ALL to resolve (rejects if any rejects)
const [users, posts] = await Promise.all([p1, p2]);

// Resolve as soon as ONE resolves
const first = await Promise.race([p1, p2]);

// Wait for ALL, regardless of success/failure
const results = await Promise.allSettled([p1, p2]);
results.forEach(r => {
  if (r.status === "fulfilled") console.log(r.value);
  else console.error(r.reason);
});

3.7 process.nextTick vs setImmediate

setImmediate(() => console.log("setImmediate"));
process.nextTick(() => console.log("nextTick"));
Promise.resolve().then(() => console.log("Promise microtask"));
console.log("synchronous");

Output order:

synchronous
nextTick
Promise microtask
setImmediate

process.nextTick fires before the next event loop iteration — before Promises. setImmediate fires in the check phase of the event loop.
