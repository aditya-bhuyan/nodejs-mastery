Chapter 4 — File System & Streams Intermediate

4.1 The fs Module

The built-in fs module exposes both synchronous and asynchronous APIs for every file-system operation. Always prefer the async forms in production code — they don't block the event loop.

const fs = require("fs");
const fsp = require("fs/promises"); // Promise-based API (Node.js 14+)

// Sync (blocks the event loop — use only at startup)
const data = fs.readFileSync("./config.json", "utf8");

// Callback-style async
fs.readFile("./config.json", "utf8", (err, data) => {
  if (err) throw err;
  console.log(data);
});

// Promise / async-await (preferred)
const data = await fsp.readFile("./config.json", "utf8");

4.2 Common fs Operations

const fsp = require("fs/promises");

// Write (overwrites) a file
await fsp.writeFile("./out.txt", "hello
");

// Append to a file
await fsp.appendFile("./out.txt", "world
");

// Copy a file
await fsp.copyFile("./src.txt", "./dest.txt");

// Delete a file
await fsp.unlink("./out.txt");

// Create a directory (recursive creates parent dirs too)
await fsp.mkdir("./logs/2024", { recursive: true });

// List directory contents
const entries = await fsp.readdir("./src");

// File metadata
const stat = await fsp.stat("./package.json");
console.log(stat.size, stat.mtime);

4.3 Watching Files & Directories

const fs = require("fs");

// Watch a file for changes
fs.watch("./config.json", (eventType, filename) => {
  console.log(`Event: ${eventType} on ${filename}`);
});

// Watch a directory recursively
fs.watch("./src", { recursive: true }, (eventType, filename) => {
  console.log(`${eventType}: ${filename}`);
});

4.4 Streams — What and Why

Streams let you process data piece by piece without loading it all into memory. Critical when handling large files, HTTP responses, or real-time data.

Node.js has four stream types:

  • Readable — source of data (fs.createReadStream, HTTP request)
  • Writable — destination (fs.createWriteStream, HTTP response)
  • Duplex — both readable and writable (TCP sockets)
  • Transform — duplex that transforms data as it passes through (compression, encryption)

4.5 Reading & Writing with Streams

const fs = require("fs");

// Readable stream — fires "data" events for each chunk
const readable = fs.createReadStream("./large.csv", { encoding: "utf8" });
readable.on("data",  chunk => process.stdout.write(chunk));
readable.on("end",   ()    => console.log("\nDone reading"));
readable.on("error", err   => console.error(err.message));

// Writable stream
const writable = fs.createWriteStream("./output.txt");
writable.write("Line 1\n");
writable.write("Line 2\n");
writable.end();                 // signals no more data

4.6 Piping Streams

.pipe() connects a readable to a writable, handling backpressure automatically.

const fs   = require("fs");
const zlib = require("zlib");

// Compress a file: read → gzip transform → write
fs.createReadStream("./data.csv")
  .pipe(zlib.createGzip())
  .pipe(fs.createWriteStream("./data.csv.gz"))
  .on("finish", () => console.log("Compression complete"));

// Decompress
fs.createReadStream("./data.csv.gz")
  .pipe(zlib.createGunzip())
  .pipe(fs.createWriteStream("./data.csv"));

4.7 The pipeline Utility

stream.pipeline() is the modern replacement for .pipe() — it properly handles errors in every stage.

const { pipeline } = require("stream/promises");
const fs   = require("fs");
const zlib = require("zlib");

async function compress(src, dest) {
  await pipeline(
    fs.createReadStream(src),
    zlib.createGzip(),
    fs.createWriteStream(dest)
  );
  console.log(`Compressed ${src} → ${dest}`);
}

compress("data.csv", "data.csv.gz");
